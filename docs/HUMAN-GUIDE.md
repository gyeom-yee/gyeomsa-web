# 읽기용 가이드

- 작성일: 2026-11-10 (수정 2026-11-23: GitHub Pages 배포, 콘텐츠 파일 추가, 공개 저장소 운영 반영)
- 이 문서는 사람이 읽는 설명서다. 에이전트의 작업 근거는 `CLAUDE.md`, `PRD.md`, `SEO-GUIDE.md`이고, 이 문서는 그 셋이 왜 그렇게 쓰였는지를 풀어 쓴 것이다.
- 내용이 서로 다르면 위 세 문서가 맞다. 이 문서는 나중에 고쳐도 된다.

## 1. 한눈에 보는 구조

```
[Notion]  강의 이력을 쓰는 곳          [저장소 파일]  제공 교육, 프로젝트 경험, 고객 후기,
   │  Notion API (빌드할 때만 호출)        주요 교육 기업, 소개 페이지 경력·자격
   ▼  ◄─────────────────────────────────────┘
[GitHub Actions]  내용을 가져와 HTML 파일로 굽고(npm run build)
   │              Notion 내부 값이 섞였는지 검사한다(npm run check:dist)
   │  검사를 통과했을 때만
   ▼
[GitHub Pages + gyeomsa.com]  구워 둔 파일을 그대로 내보낸다
   │
   ▼
[방문자]  사람, 구글·네이버 크롤러, AI 크롤러
```

핵심은 **방문자가 올 때는 Notion도 서버 프로그램도 움직이지 않는다**는 점이다. 이미 구워 둔 HTML 파일을 건네줄 뿐이다. 그래서 빠르고, JS를 실행하지 않는 AI 크롤러도 본문을 전부 읽는다.

대신 치르는 값이 하나 있다. Notion에서 글을 고쳐도 **다시 빌드하기 전까지 사이트는 그대로**다. 그래서 매일 새벽 4시 17분(한국 시간)에 자동으로 다시 빌드하고, 급할 때 바로 빌드하는 버튼도 둔다(4.8).

## 2. 왜 이 구성인가

### Notion에 바로 게시하지 않는 이유
Notion 게시 페이지는 브라우저에서 JS가 실행돼야 본문이 그려진다. 구글은 JS를 실행해 읽지만 AI 크롤러 다수는 실행하지 않는다. 주소도 `notion.site` 아래라서 "내 이름 = 내 도메인"이라는 신호를 만들 수 없고, 구조화 데이터나 llms.txt를 넣을 방법이 없다.

### 그런데도 Notion을 쓰는 이유
강의 이력이 이미 Notion DB에 있다. 사이트용으로 따로 옮겨 적으면 두 곳을 관리해야 하고 결국 한쪽이 낡는다. Notion을 원본으로 두고 사이트는 거기서 읽어 가게 하면 강의 하나를 끝내고 DB에 한 줄 추가하는 것으로 사이트 갱신이 끝난다.

### 강의 이력 말고는 저장소 파일에 쓰는 이유
제공 교육, 프로젝트 경험, 고객 후기, 주요 교육 기업, 소개 페이지의 경력·자격은 저장소의 마크다운·YAML 파일에 쓴다.

- 틀이 정해진 내용이다. 제공 교육 카드는 제목, 한 줄 설명, 시간, 대상, 커리큘럼 3~5개처럼 항목이 정해져 있다. 이런 내용은 Notion 페이지의 자유로운 블록보다 항목이 정해진 파일이 맞다. 빠진 항목이 있으면 빌드가 멈춰서 알려 준다.
- 자주 바뀌지 않는다. 강의 이력처럼 매주 늘어나는 내용이 아니라서 Notion의 편집 편의가 덜 아쉽다.
- Notion에 DB를 더 만들지 않기로 했다(PRD 6장). Notion에서 읽는 대상이 하나뿐이어야 공개하면 안 되는 값이 새어 나갈 길도 하나로 좁혀진다.

대신 고치려면 파일을 열어야 한다.

### Astro를 쓰는 이유
"Notion에서 읽어 HTML로 굽는" 일을 해 주는 도구다. 기본 출력이 JS 없는 HTML이고, sitemap 생성 같은 SEO 기능이 공식 확장으로 있어서 골랐다(PRD 6장 확정). Next.js로도 같은 결과를 낼 수 있다.

### GitHub Pages에 올리는 이유
2026-11-23에 정했다.

- 저장소가 이미 GitHub에 있어서 새 서비스에 가입할 필요가 없다.
- 예약 빌드(매일 자동 빌드)를 GitHub Actions에서 바로 걸 수 있다.
- 도메인은 가비아에 그대로 두고 DNS 레코드만 추가하면 된다.
- 호스팅 쪽에 AI 봇을 막는 기능이 없어서, robots.txt에서 열어 둔 대로 AI 크롤러가 들어온다.

치르는 값도 있다.

- 저장소가 공개라서 빌드 로그도 누구나 볼 수 있다. 그래서 빌드 중에 Notion 내부 값을 로그에 찍지 않게 만들어 두었다.
- 60일 동안 커밋이 없으면 GitHub가 예약 빌드를 멈춘다(7장).

## 3. 구성 요소별 설명

| 요소 | 하는 일 | 내가 만지는 때 |
| --- | --- | --- |
| Notion 강의 이력 DB | 강의 이력의 원본 | 강의를 마칠 때마다. 가장 자주 |
| `src/content/services/` | 제공 교육. 홈 카드마다 마크다운 파일 하나 | 교육 프로그램을 넣고 빼거나 고칠 때 |
| `src/content/projects/` | 소개 페이지의 프로젝트 경험. 프로젝트마다 파일 하나 | 프로젝트를 추가할 때 |
| `src/content/reviews/` | 고객 후기. 후기마다 파일 하나 | 후기를 새로 받았을 때 |
| `src/content/clients.yaml` | 주요 교육 기업 목록(실명)과 글자 크기 | 실명으로 실을 기업이 늘 때 |
| `src/content/profile.yaml` | 소개 페이지의 경력·학력·교육 이수·자격·기술 | 경력이나 자격이 바뀔 때 |
| `src/site.config.ts` | 이름, 한 줄 소개, 이메일, 외부 링크, 소개 수정일, 검색엔진 소유 확인 값 | 소개 문구를 바꾸거나 검색엔진에 등록할 때 |
| Notion 통합(Integration) | 외부 프로그램이 내 DB를 읽게 해 주는 출입증 | 처음 한 번 만들고 DB에 연결 |
| `.env` | 출입증(토큰)과 DB ID를 적어 두는 내 컴퓨터 전용 파일 | 처음 한 번 |
| GitHub Secrets | 같은 토큰과 DB ID를 GitHub Actions에 건네는 곳 | 처음 한 번(2026-11-23에 넣었다). 토큰을 새로 발급하면 함께 바꾼다 |
| `src/lib/notion/` | Notion을 호출하고 공개 항목만 골라 수치를 계산하는 코드 | 거의 없음. DB 속성을 바꿨을 때 |
| `src/pages/` | 페이지 하나하나의 틀 | 페이지를 추가하거나 구성을 바꿀 때 |
| `src/layouts/` | 모든 페이지 공통의 `<head>`와 뼈대 | 메타 태그 규칙을 바꿀 때 |
| `.github/workflows/deploy.yml` | 빌드 → 검사 → 배포 순서와 예약 빌드 시간 | 거의 없음. 예약 시간을 바꿀 때 |
| `.githooks/pre-commit` | 커밋 직전 비공개 정보 검사 | 거의 없음. 숨길 단어는 `denylist.local`에 더한다(4.9) |
| `dist/` | 빌드 결과물. 매번 새로 만들어진다 | 직접 고치지 않는다 |
| GitHub Pages | `dist/`를 인터넷에 내보내는 호스팅. HTTPS 인증서도 알아서 갱신한다 | 거의 없음 |
| 도메인 gyeomsa.com | 사이트 주소. 가비아에 등록했고 DNS도 가비아에서 관리한다 | 매년 갱신(지금 만료일 2027-11-18) |

`dist/` 안의 파일을 손으로 고쳐도 다음 빌드에서 덮어써진다. 고칠 것이 있으면 Notion이나 `src/`를 고친다.

## 4. 상황별 작업 흐름

### 4.1 처음 한 번 하는 준비
1. Notion에서 통합을 만들고 토큰을 받는다.
2. 강의 이력 DB에 그 통합을 연결한다. 연결하지 않은 DB는 토큰이 있어도 읽히지 않는다.
3. 프로젝트 폴더에 `.env`를 만들고 토큰과 DB ID를 적는다(`.env.example`을 복사하면 된다).
4. `npm install`을 실행한다.
5. `git config core.hooksPath .githooks`로 커밋 직전 검사를 연결한다.
6. GitHub 저장소의 Settings → Secrets and variables → Actions에 `.env`의 두 값을 같은 이름으로 넣는다. 터미널에서 `gh secret set -f .env`로 넣어도 된다.

1·2·6은 이미 해 두었다. 다른 컴퓨터에서 작업을 시작할 때는 3~5를 다시 한다. `.env`는 저장소에 올라가지 않기 때문이다.

### 4.2 강의 이력을 한 건 추가할 때
1. Notion 강의 이력 DB에 행을 추가한다.
2. `공개기업명`을 적는다. 기업은 `[이니셜]사 [업종] [규모]`(예: S사 반도체 대기업), 공공기관과 대학은 실제 이름 그대로 쓴다. 실명 공개를 정한 기업도 실제 이름을 쓴다. 실명으로 바꿨다면 `src/content/clients.yaml`에도 추가한다. 같은 그룹의 다른 법인·사업부는 서로 다른 표기를 쓴다.
3. `공개과정명`을 적는다. 같은 기업에서 같은 과정을 여러 차수 했다면 같은 값을 골라야 강의 이력 표에서 한 줄로 묶인다.
4. 사이트의 표와 수치에 쓰이는 값을 채운다.
   - `날짜`: 표의 시기와 최신순 정렬
   - `강의시간`, `수강인원`: 누적 교육 참여시간과 누적 수강인원
   - `역할`: `강사` 또는 `튜터&코치`. 화면에는 주강사·실습 코치로 나온다. 다른 값을 쓰면 수치 요약의 주강사·실습 코치 시간 합이 전체와 어긋난다
   - `강의평점`: 주강사로 진행하고 만족도 점수(5점 만점)를 받았을 때만. 홈의 "주강사 강의 만족도" 평균에 들어간다
5. 강의를 마치면 `참여상태`를 `완료`로 바꾼다.
6. 다음 날 새벽 자동 빌드 때 사이트에 반영된다. 바로 반영하려면 4.8의 수동 빌드를 쓴다.

`공개과정명`이나 `공개기업명` 중 하나라도 비어 있으면 그 행은 사이트에 나가지 않는다. 내부용 `강의명`, `기업명`, `교육기관`은 어떤 경우에도 사이트에 나가지 않는다.

코드는 건드리지 않는다. 익명 처리를 코드가 아니라 Notion에서 하는 이유는, 무엇을 가릴지 판단하는 사람이 나이기 때문이다. 코드에 규칙으로 넣으면 예외가 생길 때마다 코드를 고쳐야 한다.

### 4.3 교육 프로그램을 추가하거나 고칠 때
제공 교육은 별도 페이지 없이 홈의 "주요 교육 프로그램" 카드로만 나온다. 파일 하나가 카드 하나다.

1. `src/content/services/`에 `{slug}.md` 파일을 만든다. 같은 폴더의 `_template.md`를 복사하면 된다. 파일 이름은 주소가 아니라 카드를 구분하는 이름이다. 이름이 `_`로 시작하는 파일은 사이트에 나오지 않는다.
2. 파일 머리말에 제목(`title`), 한 줄 설명(`description`), 순서(`order`), 시간(`duration`), 대상(`audience`), 주요 커리큘럼(`curriculum`, 3~5개)을 적는다. 본문은 쓰지 않는다.
3. `courses`에 이 교육에 해당하는 강의 이력의 `공개과정명`을 Notion 값과 글자까지 똑같이 적는다. 빌드 때 그 과정들의 `공개기업명`이 "진행 경험" 태그로 붙는다. 글자가 다르면 빌드 로그에 경고가 뜨고 태그가 빠진다.
4. 커밋하고 push하면 자동으로 배포된다. 홈 카드와 llms.txt에 함께 들어간다.

카드를 나누는 기준은 "이 교육만 따로 문의가 올 수 있는가"다. 지금은 네 개다.

Claude Code에 초안을 맡길 때는 대상, 시간, 결과물 같은 사실을 내가 먼저 주고 문장만 다듬게 한다. CLAUDE.md에 "요청 없이 내용을 지어내 채우지 않는다"는 규칙을 넣어 두었다.

### 4.4 프로젝트·후기·주요 교육 기업을 고칠 때
모두 같은 폴더의 `_template.md`나 파일 첫머리 주석에 적는 법이 있다.

**프로젝트 경험** (`src/content/projects/`)
- 소개 페이지의 "프로젝트 경험" 섹션에만 나온다. 별도 페이지는 없다.
- `period`는 `2026.03 ~ 2026.06`, `2026.03 ~ 현재`, `2026.03` 중 하나로 적는다. 목록은 끝난 시기가 최근인 순으로 자동 정렬된다.
- `affiliation`에는 의뢰한 고객사가 아니라 내가 일한 곳이나 참여한 과제를 적는다.
- 증빙 링크(`links`)의 이름은 "GitHub 저장소"처럼 링크 내용을 말하는 문구로 쓴다. "여기"는 쓰지 않는다.
- 경력 항목에서 이 프로젝트로 연결하려면 `profile.yaml`의 경력 항목에 `project: 파일이름`을 적는다(4.5).

**고객 후기** (`src/content/reviews/`)
1. 원본 설문은 `raw_reviews/`에 둔다. 응답자 정보가 들어 있어 저장소에 올라가지 않는다.
2. 사이트에 실을 문장을 내가 고른다.
3. 고른 문장만 후기 하나당 파일 하나로 옮긴다. 문장을 고치거나 다듬지 않는다. 홈에 "고치지 않고 그대로 옮겼습니다"라고 적혀 있기 때문이다. 작성자 실명은 적지 않는다.

**주요 교육 기업** (`src/content/clients.yaml`)
- 홈과 소개 페이지에 글자 구름으로 나온다. 실명으로 공개해도 되는 곳만 적는다. 강의 이력 표의 익명 표기는 그대로 둔다.
- `size`는 1~4이고 클수록 글자가 커진다. 교육 규모를 보고 내가 정한다.
- 적은 순서대로 배치된다.

### 4.5 소개 페이지의 경력·학력·자격을 고칠 때
`src/content/profile.yaml`을 고친다. 파일 첫머리 주석에 형식이 있다.

- 경력에는 기업별 수강인원·강의시간·횟수, 익명 표기 기업명을 적지 않는다. 소속 회사명은 강의 운영사여도 실명으로 적는다(2026-11-18 결정).
- 자격에는 자격번호를 적지 않는다. 확인 링크(`url`)에는 발급기관의 배지·인증서 페이지만 넣는다.
- 자격에 만료일(`expires`)을 적어 두면, 만료된 뒤에는 사이트에서 저절로 빠지고 빌드 로그에 정리하라는 경고가 뜬다.
- **소개 내용을 바꾼 날에는 `src/site.config.ts`의 `profileModified`도 그날 날짜로 바꾼다.** 검색엔진에 "소개가 이날 바뀌었다"고 알리는 값이라, 빌드 날짜가 아니라 내용이 바뀐 날을 손으로 적는다.
- 이력서 PDF가 준비되면 `public/kim-yungyeom-resume.pdf`로 넣는다. 파일이 생기면 소개 페이지의 내려받기 버튼이 켜진다.

### 4.6 디자인이나 페이지 구성을 바꿀 때
이때만 코드를 고친다. Claude Code에 맡길 때는 바꾸려는 내용이 PRD의 범위 안인지 먼저 보고, 범위를 넘으면 PRD부터 고친 뒤 작업을 시킨다. 문서와 코드가 어긋나면 다음 세션의 에이전트가 낡은 문서를 믿고 되돌려 놓는 일이 생긴다.

### 4.7 내 컴퓨터에서 확인할 때
```
npm run dev         고치면서 바로 확인. Notion 내용은 시작할 때 한 번 읽는다
npm run build       실제 배포될 결과물을 dist/에 만든다
npm run preview     dist/를 그대로 띄워 본다
npm run check       타입 검사
npm run check:dist  dist/에 Notion 내부 값·토큰이 섞이지 않았는지 검사
```
검색 노출과 관련된 확인(본문이 HTML에 있는지, 메타 태그가 맞는지)은 `dev`가 아니라 `build` 결과로 한다. 개발 서버는 배포 결과와 출력이 조금 다르다.

### 4.8 배포
GitHub Pages로 배포한다. 설정은 `.github/workflows/deploy.yml`에 있다.

**언제 배포되나**
- `main`에 push했을 때
- 매일 04:17(한국 시간). Notion만 고친 날을 위한 예약 빌드다
- 내가 버튼을 눌렀을 때. GitHub 저장소의 Actions 탭 → Deploy → Run workflow. 터미널에서는 `gh workflow run deploy.yml`

**무슨 일이 일어나나**
1. GitHub Actions가 Notion에서 강의 이력을 읽어 빌드한다. 토큰은 GitHub Secrets에서 받는다.
2. `check:dist`로 빌드 결과에 Notion 내부 값·토큰이 섞이지 않았는지 검사한다.
3. 검사를 통과하면 GitHub Pages에 올린다. 보통 1분 안팎에 끝난다.

빌드나 검사가 실패하면 배포하지 않으므로 직전 사이트가 그대로 남는다. 실패하면 GitHub가 메일로 알려 준다. Actions 탭에서 어느 단계가 실패했는지 볼 수 있다.

**도메인과 HTTPS**
- 가비아 DNS에 A 레코드 4개(`185.199.108.153`~`185.199.111.153`)와 `www` CNAME(`gyeom-yee.github.io.`)을 넣어 GitHub Pages로 연결했다.
- HTTPS 인증서는 GitHub가 발급하고 갱신한다. 내가 할 일은 없다.
- `www.gyeomsa.com`, `http://`, 끝에 `/`가 빠진 주소는 모두 `https://gyeomsa.com/…`으로 리디렉션된다.

### 4.9 GitHub에 올릴 때 지킬 것
저장소는 공개다. **사이트에 나가지 않는 정보는 저장소에도 두지 않는다**가 기준이다(CLAUDE.md "공개 저장소 규칙").

- 커밋 직전에 `.githooks/pre-commit`이 검사한다. 대상은 제외 폴더(`naming/`, `references/`, `raw_reviews/` 등), Notion 토큰 형식, `.env`의 실제 값, 비공개 단어 목록이다. 걸리면 커밋이 멈춘다. 검사를 건너뛰는 `--no-verify`는 쓰지 않는다.
- 저장소에 적으면 안 되는 이름이 새로 생기면 `.githooks/denylist.local`에 한 줄 더한다. 이 파일 자체는 저장소에 올라가지 않는다.
- 한 번 push한 커밋은 공개 기록이다. 나중에 파일을 고쳐도 이전 커밋에는 남는다(7장).

## 5. 검색엔진과 AI가 사이트를 읽는 과정

1. **발견**: 크롤러가 다른 사이트의 링크나 내가 제출한 sitemap으로 주소를 안다. 새 도메인은 아무도 링크하지 않으므로 Search Console 등에 직접 등록해야 시작된다.
2. **수집**: 크롤러가 robots.txt를 보고 허용된 주소의 HTML을 가져간다.
3. **이해**: title, 제목 태그, 본문, 구조화 데이터로 "누구에 대한 무슨 페이지인지" 판단한다.
4. **색인**: 검색 결과에 쓸 수 있도록 저장한다. 수집됐다고 전부 색인되지는 않는다.
5. **순위**: 검색어와의 관련도, 다른 사이트가 이 사이트를 얼마나 가리키는지 등으로 줄을 세운다.

AI 답변은 두 갈래로 내 사이트를 쓴다.
- **실시간 검색**: 질문을 받은 순간 검색엔진을 돌려 상위 결과 몇 개를 읽고 답을 쓴다. 그래서 일반 검색 순위가 높아야 AI 답변에도 들어간다. SEO가 GEO의 바탕이라는 말이 이 뜻이다.
- **학습 데이터**: 모델을 만들 때 읽은 글. 반영에 몇 달에서 몇 년이 걸리고 내가 통제할 수 없다.

지금 손댈 수 있는 것은 실시간 검색 쪽이다.

### 검색엔진에 등록하는 법
Google Search Console, 네이버 서치어드바이저, Bing Webmaster Tools 세 곳에 등록한다. 진행 상황은 `SEO-GUIDE.md` "배포한 뒤" 체크리스트에 표시한다.

1. 사이트 주소 `https://gyeomsa.com/`을 등록한다.
2. 소유 확인 방법을 고른다.
   - HTML 태그 방식이면 받은 태그의 `content` 값만 `src/site.config.ts`의 `verification`(`google`, `naver`, `bing`)에 넣고 push한다. 공통 레이아웃이 모든 페이지 `<head>`에 태그를 넣는다. 네이버는 이 방식으로 넣었다(2026-11-23).
   - DNS 방식이면 가비아 DNS 설정에 TXT 레코드를 추가한다.
3. 확인이 끝나면 sitemap `https://gyeomsa.com/sitemap-index.xml`을 제출한다.

### 기대치
- 새 도메인이 색인되기까지 보통 며칠에서 몇 주가 걸린다.
- 이름 검색 순위는 사이트 완성도만으로 정해지지 않는다. LinkedIn 같은 외부 프로필이 이 사이트를 가리키는지, 같은 이름의 다른 사람이 얼마나 알려져 있는지가 함께 작용한다.
- llms.txt는 넣어 두지만 주요 AI 검색이 이 파일을 쓴다고 공식적으로 밝힌 적은 없다. 효과를 기대하고 넣는 것이 아니라 비용이 거의 없어서 넣는 것이다.

## 7. 자주 헷갈리는 것

**애니메이션을 넣으면 노출이 떨어지나.**
글자가 HTML에 들어 있으면 떨어지지 않는다. 크롤러는 화면이 어떻게 움직이는지 보지 않고 HTML의 글자를 읽는다. 문제가 되는 경우는 셋이다. 본문을 JS로 불러와 그릴 때, 글자를 영상이나 이미지 안에 넣을 때, 효과 때문에 로딩이 느려질 때. 그래서 "JS를 꺼도 본문이 전부 보인다"를 완료 기준에 넣었다.

**Notion에서 고쳤는데 사이트가 안 바뀐다.**
다음 날 새벽 4시 17분 예약 빌드 때 바뀐다. 바로 반영하려면 Actions 탭에서 Deploy → Run workflow를 누른다(4.8).

**예약 빌드가 멈췄다는 메일이 왔다.**
공개 저장소에 60일 동안 커밋이 없으면 GitHub가 예약 빌드를 멈춘다. Actions 탭 → Deploy에서 다시 켜면 된다. 그사이에도 push나 수동 실행으로는 배포된다.

**배포가 실패했다는 메일이 왔다.**
Actions 탭에서 실패한 단계를 본다. "공개 검사" 단계가 실패했다면 Notion 내부 값이 사이트에 섞일 뻔한 것이니, 로그에 가려서 나온 값을 보고 Notion이나 파일을 고친다. 그동안 사이트는 직전 상태로 남아 있다.

**`공개기업명`을 지웠는데 검색 결과에 아직 나온다.**
다시 빌드하면 사이트에서는 사라지지만 검색엔진에 저장된 사본은 한동안 남는다. 급하면 Search Console의 삭제 요청을 쓴다. 그래서 밝히면 안 되는 내용은 처음부터 `공개기업명`과 `공개과정명`에 적지 않는 것이 유일하게 확실한 방법이다.

**저장소에 올리면 안 되는 내용을 push했다.**
파일을 고쳐 다시 커밋해도 이전 커밋에 남는다. 커밋 기록을 고쳐 강제 push해야 한다. 그래도 GitHub는 옛 커밋을 커밋 주소로 한동안 보여 줄 수 있다. 완전히 지우려면 GitHub 지원팀에 요청하거나 저장소를 지우고 다시 만든다. 2026-11-23 배포 전에 실제로 이 작업을 했다. 그래서 커밋 직전 검사(4.9)와 비공개 단어 목록을 둔다.

**토큰을 실수로 커밋했다.**
위와 같이 기록에 남는다. Notion에서 토큰을 폐기하고 새로 발급받는 것이 먼저다. 새 토큰은 `.env`와 GitHub Secrets 두 곳에 넣는다.

**이미지가 며칠 뒤에 깨진다.**
Notion이 주는 이미지 주소는 약 한 시간 뒤 만료되는 임시 주소다. 지금 사이트는 Notion 이미지를 쓰지 않는다. 나중에 쓰게 되면 빌드할 때 이미지를 내려받아 사이트에 포함해야 한다.

**`www`가 붙은 주소와 안 붙은 주소가 둘 다 열린다.**
검색엔진은 둘을 다른 사이트로 볼 수 있어서 하나로 정하고 나머지는 리디렉션해야 한다. 이 사이트는 `https://gyeomsa.com/`으로 정했고, GitHub Pages가 `www`를 이 주소로 리디렉션한다.

**Rich Results Test에 홈을 넣었더니 "감지된 항목 없음"이 나온다.**
정상이다. 이 도구는 구글이 검색 결과를 꾸며 보여 주는 종류(탐색경로, 프로필 페이지, FAQ 등)만 센다. 홈에 넣은 Person과 WebSite는 그 목록에 없다. 이 둘은 검색엔진과 AI가 "이 사람이 누구인지" 이해하라고 넣은 것이다. Rich Results Test는 소개 페이지(`/about/`)로 확인하고, 홈은 Schema Markup Validator로 확인한다.

### 페이지 안의 표식

| 용어 | 뜻 |
| --- | --- |
| 메타 태그 | 화면에는 안 보이고 `<head>`에 들어가는 페이지 정보 |
| title | 브라우저 탭과 검색 결과 제목에 쓰이는 문구 |
| description | 검색 결과 제목 아래에 보이는 설명 후보 |
| canonical | 같은 내용이 여러 주소로 열릴 때 "대표 주소는 이것"이라고 알리는 태그 |
| OG 태그 | 카카오톡이나 LinkedIn에 링크를 붙였을 때 뜨는 제목·설명·이미지를 정하는 태그 |
| 구조화 데이터 | "이 페이지는 사람 소개이고 이름은 무엇, 직함은 무엇"처럼 기계가 읽는 형식으로 적은 정보 |
| JSON-LD | 구조화 데이터를 적는 형식. `<script>` 태그 안에 JSON으로 쓴다 |
| schema.org | 구조화 데이터에 쓰는 단어 사전. Person, Course 같은 타입이 여기서 온다 |
| sameAs | 구조화 데이터에서 "이 프로필들도 같은 사람이다"라고 연결하는 항목 |
| dateModified | 구조화 데이터에서 "이 페이지 내용이 언제 바뀌었나"를 알리는 값. 소개 페이지는 `profileModified`로 정한다 |
| alt | 이미지를 글로 설명한 문구. 크롤러와 화면 낭독기가 읽는다 |

### 주소

| 용어 | 뜻 |
| --- | --- |
| 도메인 | 사이트의 이름 주소 |
| DNS | 도메인 이름을 실제 서버 주소로 바꿔 주는 전화번호부. gyeomsa.com은 가비아에서 관리한다 |
| A 레코드 / CNAME | DNS에 적는 줄. A는 "이 이름은 이 IP", CNAME은 "이 이름은 저 이름과 같다" |
| HTTPS / 인증서 | 주소창의 자물쇠. 주고받는 내용을 암호화한다. GitHub Pages가 인증서를 자동 발급·갱신한다 |

| 301 리디렉션 | "이 주소는 영구히 저쪽으로 옮겼다"는 응답. 검색 평가가 새 주소로 넘어간다 |
| 클로킹 | 크롤러에게만 사람과 다른 내용을 보여 주는 것. 검색엔진 정책 위반이라 금지사항에 넣었다 |

| 정적 사이트 | 미리 만들어 둔 HTML 파일을 그대로 내보내는 사이트 |
| SSG | 정적 사이트 생성기. 빌드할 때 HTML을 전부 만들어 두는 방식 |
| SPA / CSR | 빈 HTML을 보낸 뒤 브라우저에서 JS로 화면을 그리는 방식. AI 크롤러에 불리하다 |
| 빌드 | 소스 코드와 내용을 합쳐 배포할 파일을 만드는 과정 |
| 배포 | 빌드 결과를 호스팅에 올려 실제 주소에서 보이게 하는 것 |
| 호스팅 | 사이트 파일을 인터넷에 올려 두는 서비스. 이 사이트는 GitHub Pages |
| CMS | 내용을 쓰고 관리하는 도구. 이 프로젝트에서는 Notion |
| Notion API | 프로그램이 Notion 내용을 읽고 쓰는 통로 |
| 통합(Integration) | Notion에서 외부 프로그램에 발급하는 접근 권한 단위. 여기서 토큰이 나온다 |
| 토큰 | 프로그램이 "나는 허락받았다"고 증명하는 비밀 문자열. 비밀번호처럼 다룬다 |
| 환경변수 / `.env` | 코드 밖에 두는 설정값과 그것을 적는 파일. 토큰을 여기에 둔다 |
| GitHub Secrets | GitHub Actions가 쓸 비밀값을 넣어 두는 곳. 넣은 값은 다시 볼 수 없고 로그에도 가려져 나온다 |
| `.gitignore` | Git이 저장소에 올리지 않을 파일 목록. `.env`가 여기 들어간다 |
| GitHub Actions | GitHub에서 정해진 때에 명령을 자동 실행하는 기능. 빌드·검사·배포와 예약 빌드에 쓴다 |
| pre-commit 훅 | 커밋 직전에 자동으로 도는 검사. 걸리면 커밋이 멈춘다 |
| 강제 push | 원격 저장소의 기록을 내 기록으로 덮어쓰는 push. 기록을 고쳤을 때만 쓴다 |
