## 1. 목적

1. **이름 검색 노출**: 구글에서 이름을 검색했을 때 이 사이트가 가장 위에 나온다.
2. **AI 답변 인용**: ChatGPT, Perplexity, Gemini, Claude 같은 AI가 이 사람에 대해 답할 때 이 사이트를 근거로 쓴다.
3. **강의 문의 전환**: 방문한 기업 교육 담당자가 강의 이력과 제공 교육을 확인하고 문의한다.

1번과 2번은 사이트를 잘 만든다고 보장되는 결과가 아니다. 외부 프로필의 링크, 색인에 걸리는 시간, 같은 이름의 다른 사람에 따라 달라진다. 그래서 이 문서의 완료 기준(5장)은 "노출에 필요한 조건을 갖췄는가"로 잡고, 실제 노출은 배포 후 별도로 추적한다.

## 3. 사이트맵과 페이지 구성

```
/                      홈
/about/                소개
/lectures/             강의 이력
/projects/             프로젝트 사례
/contact/              문의
/robots.txt            크롤러 안내
/sitemap-index.xml     사이트맵
/llms.txt              AI용 사이트 요약
```

### 홈 `/`
- h1에 이름이 들어간다. 구호를 크게 보여 주더라도 h1을 구호만으로 쓰지 않는다.
- 첫 문단: 누구이고 무엇을 가르치는지 두세 문장으로 끝낸다. AI가 그대로 인용할 수 있는 문장이어야 한다.
- 첫 화면에 프로필 사진 2장을 겹쳐 둔다(4.3의 F13).
- 수치 요약: 강의 이력에서 계산한 누적 강의시간, 누적 수강인원, 기업·기관 수(4.1의 F2-1). 숫자는 빌드 결과 HTML에 실제 값으로 들어 있어야 한다. 숫자가 올라가는 효과를 넣더라도 HTML의 초기값을 0으로 두지 않는다.
- 주요 교육 기업: 실명으로 공개하는 기업 이름만 글자 워드클라우드로 보여 준다. 과정명, 시기, 횟수는 붙이지 않는다. 로고 이미지는 쓰지 않는다(로고는 사용 허락이 필요하다).
  - `clients.yaml`의 `size`(1~4)로 글자 크기·굵기·색 농도를 정한다. 적힌 순서대로 가운데 정렬로 배치한다.
  - 마크업은 `<ul>` 목록이다. 글자를 회전하지 않는다. 캔버스·SVG로 그리지 않고 HTML 글자로 둔다.
  - 클라우드 아래에 "글자 크기는 교육 규모를 나타냅니다"를 한 줄 둔다.
- 주요 교육 프로그램 카드. 제공 교육은 별도 페이지 없이 이 카드로만 보여 준다.
  - 섹션 첫머리에 "정해진 커리큘럼 목록이 아니라 기관에 맞춰 조정한다"는 안내를 한 줄 둔다.
  - 카드 구성(위에서 아래로): 번호, 시간 배지, 제목, 한 줄 설명, 대상, 진행 경험, 주요 커리큘럼 3~5개.
  - 진행 경험은 파일의 `courses`(공개과정명 목록)와 일치하는 강의 이력의 `공개기업명`을 태그로 보여 준다. 실명 기업 목록(`clients.yaml`)과 섞지 않는다.
  - 카드 아래에 문의 버튼을 둔다.
- 최근 강의 이력 5건(강의 이력으로 연결)
- 프로젝트 사례 요약(일부만 보여 주고 프로젝트 사례 페이지로 연결)
- 고객 후기 카드
- 문의 버튼

### 소개 `/about/`
- 한 줄 소개, 경력 요약, 다루는 기술과 주제
- 프로필 사진 2장(홈과 같은 구성, 4.3의 F13)
- 주요 교육 기업(홈과 같은 목록)
- 이력서 PDF 내려받기 버튼. PDF 파일이 없으면 버튼을 비활성 상태로 보여 준다(링크 없음, "이력서 준비 중" 표기). 파일을 넣고 다시 빌드하면 내려받기 버튼으로 바뀐다. PDF 내용은 사이트 본문과 어긋나지 않게 맞춘다.
- 외부 프로필 링크: LinkedIn, GitHub
- 이름 검색의 도착 페이지이므로 이름이 title, h1, 첫 문단에 모두 들어간다.

### 강의 이력 `/lectures/`
- Notion 강의 이력 DB에서 `공개과정명`과 `공개기업명`이 모두 채워져 있고 `참여상태`가 `완료`인 항목만 표로 보여준다.
- DB는 차수마다 한 행이다. 표에서는 `공개기업명`과 `공개과정명`이 같은 행을 한 줄로 묶는다.
- 열: 시기(묶인 행의 첫 달~마지막 달), 기업(`공개기업명`), 과정(`공개과정명`), 역할(`역할`), 횟수·시간(묶인 행 수와 `강의시간` 합계).
- 역할은 DB 값(`강사`, `튜터&코치`)을 그대로 보여 준다. 운영사(`교육기관`)는 싣지 않는다.
- 기업명 익명화와 과정명 풀어쓰기는 Notion의 `공개기업명`, `공개과정명` 값으로 한다. 코드에서 익명 처리하지 않는다. 원래의 `강의명`과 `기업명`은 화면, 메타 태그, JSON-LD, llms.txt 어디에도 내보내지 않는다.
- `공개기업명` 표기 규칙: 기업은 `[이니셜]사 [업종] [규모]`(예: S사 반도체 대기업), 공공기관과 대학은 실제 이름 그대로. 실명 공개를 정한 기업은 실제 이름을 쓴다(예: 문토). 같은 그룹의 다른 법인·사업부는 서로 다른 표기를 쓴다.

### 프로젝트 사례 `/projects/`
- 강의 외에 직접 수행한 컨설팅·개발 프로젝트를 카드로 나열한다. 프로젝트마다 별도 페이지를 만들지 않고 이 한 페이지에 모두 싣는다.
- 카드 구성: 제목, 기간, 고객사 표기명, 설명, 사용 기술 태그.
- 고객사명을 밝힐 수 없는 건은 파일에 익명 표현을 적어 그대로 내보낸다.
- 성과 수치는 근거가 있는 것만 적는다.

### 고객 후기(홈의 섹션)
- 별도 페이지 없이 홈에 카드로 보여 준다.
- 카드 구성: 후기 본문, 소속 표기, 역할(수강생, 교육 담당자 등). 작성자 실명은 싣지 않는다.
- 실제로 받은 후기만 싣는다. 문장을 지어내거나 고쳐 쓰지 않는다.
- 후기는 글자로 싣는다. 후기 캡처 이미지만으로 대신하지 않는다.
- 파일의 `course`(교육명)와 `date`(시기)는 선택 값이다. 비어 있으면 카드에서 그 줄을 빼고, 빈 칸이나 자리 채우기 문구를 내보내지 않는다.

### 문의 `/contact/`
- 문의 수단은 이메일이다. 주소를 글자로 적고 메일 쓰기 버튼(mailto)을 둔다. 폼은 만들지 않는다.
- 문의할 때 알려주면 좋은 정보(인원, 일정, 주제).

## 4. 기능 요구사항

### 4.1 콘텐츠 파이프라인
내용의 출처는 Notion과 저장소 파일 둘이다.

| 내용 | 출처 | 고치는 곳 |
| --- | --- | --- |
| 강의 이력, 수치 요약 | Notion 강의 이력 DB | Notion |
| 제공 교육(홈의 교육 프로그램 카드) | 저장소의 `src/content/services/{slug}.md` | 파일 |
| 프로젝트 사례 | 저장소의 `src/content/projects/{slug}.md` | 파일 |
| 고객 후기 | 저장소의 `src/content/reviews/{slug}.md` | 파일 |
| 주요 교육 기업 | 저장소의 `src/content/clients.yaml` | 파일 |
| 이력서 PDF, 프로필 사진 | 저장소의 파일 | 파일 |

- F1. 빌드 시점에 Notion API로 강의 이력 DB를 읽는다. Notion에서 읽는 것은 이것 하나다.
- F2. 강의 이력은 `공개과정명`과 `공개기업명`이 모두 채워진 항목만 가져온다. 하나라도 빈 항목은 빌드 결과 어디에도 남지 않는다. `공개` 체크박스는 두지 않는다.
- F2-1. 홈의 수치 요약은 F2로 가져온 강의 이력에서 빌드 때 계산한다. F2에서 빠진 항목은 세지 않는다. 기업·기관 수는 `공개기업명`의 종류 수다. 숫자를 코드나 다른 파일에 따로 적지 않고, 사이트의 다른 곳에서 같은 숫자를 쓸 때도 이 계산 결과를 쓴다.
- F3. Notion 이미지를 쓰게 되면 빌드 때 내려받아 사이트에 포함한다.
- F4. Notion 토큰과 강의 이력 DB ID는 환경변수로만 받는다.
- F5. 제공 교육은 카드마다 마크다운 파일 하나로 관리한다. 파일 머리말(frontmatter)에 제목, 한 줄 설명, 표시 순서, 시간, 대상, 주요 커리큘럼, 진행 경험용 공개과정명 목록(`courses`)을 적는다. 본문은 쓰지 않는다. 필수 값이 빠진 파일은 빌드에서 오류로 잡는다. `courses`에 적은 이름이 공개 강의 이력에 없으면 빌드에서 경고한다.
- F5-1. 홈의 교육 프로그램 카드와 llms.txt의 제공 교육 목록은 모두 이 파일들에서 만든다. 교육 목록을 다른 곳에 따로 적지 않는다.
- F5-2. 프로젝트 사례와 고객 후기도 항목마다 마크다운 파일 하나로 관리한다. 홈의 요약과 프로젝트 사례 페이지는 같은 파일에서 만든다. 필수 값이 빠진 파일은 빌드에서 오류로 잡는다.
- F5-3. 프로젝트 사례와 고객 후기의 문구는 사용자가 쓴다. 파일이 하나도 없으면 해당 섹션과 페이지를 만들지 않는다.
- F5-4. 주요 교육 기업 목록은 `src/content/clients.yaml`에 사용자가 직접 적는다. 항목마다 `name`과 `size`(1~4)를 둔다. Notion의 `기업명`에서 만들지 않고, `size`도 코드가 강의 이력에서 계산하지 않는다. 목록이 비어 있으면 섹션을 만들지 않는다. 강의 이력 표의 익명 표기와 이 목록의 실명을 화면이나 데이터에서 서로 연결하지 않는다.

강의 이력 DB(`강의이력DB`)의 실제 속성(2026-11-16 확인):

| 속성 | 종류 | 쓰임 |
| --- | --- | --- |
| 공개과정명 | 선택 | 사이트에 보이는 과정명. 차수를 묶는 기준 |
| 공개기업명 | 선택 | 사이트에 보이는 기업 표기 |
| 강의명 | 제목 | 내부용. `[기업] 과정명_N차` 형태. 사이트에 쓰지 않는다 |
| 날짜 | 날짜 | 시기 |
| 기업명 | 선택 | 내부용 실명. 사이트에 쓰지 않는다 |
| 교육기관 | 선택 | 교육 운영사. `개인`은 직접 수주한 건. 사이트에 쓰지 않는다 |
| 역할 | 선택 | `강사`, `튜터&코치` |
| 강의시간 | 숫자 | 시간 합계 |
| 수강인원 | 숫자 | 인원 합계 |
| 참여상태 | 상태 | `시작 전`, `진행중`, `완료` |
| 강의평점, 장소, 관련링크, 관계형 3개(강의커리큘럼, 기술스택DB, 강의QA_DB) | | 사이트에 쓰지 않는다 |

- `공개과정명`, `공개기업명`은 2026-11-16에 추가했고 95행 모두 값을 채웠다.
- `참여상태`가 `완료`가 아닌 항목은 두 속성이 채워져 있어도 내보내지 않는다.

파일 양식과 위치

| 내용 | 위치 | 양식 |
| --- | --- | --- |
| 제공 교육 | `src/content/services/{slug}.md` | 같은 폴더의 `_template.md` |
| 프로젝트 사례 | `src/content/projects/{slug}.md` | 같은 폴더의 `_template.md` |
| 고객 후기 | `src/content/reviews/{slug}.md` | 같은 폴더의 `_template.md` |
| 프로필 사진(대표) | `src/assets/profile.jpg` | 세로형 인물 사진, 긴 변 1200px 이상. 빌드 때 WebP로 변환한다. JSON-LD `image`에 쓴다 |
| 프로필 사진(강의 현장) | `src/assets/profile-lecture.jpg` | 가로형 강의 사진, 긴 변 1200px 이상. 빌드 때 WebP로 변환한다 |
| 이력서 PDF | `public/kim-yungyeom-resume.pdf` | 파일 이름을 바꾸지 않고 덮어쓴다 |

- 이름이 `_`로 시작하는 파일은 빌드에서 제외한다.

### 4.2 검색·AI 노출
세부 규칙은 `docs/SEO-GUIDE.md`를 따른다.
- F6. 모든 페이지가 정적 HTML로 출력되고 본문이 HTML 안에 있다.
- F7. 페이지마다 title, description, canonical, OG 태그를 가진다.
- F8. JSON-LD 구조화 데이터를 넣는다(홈 WebSite, 소개 ProfilePage와 Person, 하위 페이지 BreadcrumbList).
- F9. sitemap, robots.txt, llms.txt를 빌드 때 생성한다.

### 4.3 화면
